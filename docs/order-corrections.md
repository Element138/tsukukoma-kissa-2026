# Order corrections and wait statistics

Notes may be edited after completion or failure by POS/admin users from the order book. Sales order inspection also lets POS/admin users stage a note and the order's wait-statistics exclusion together, then commit with **すべて保存**. Closing the panel or switching orders/dates warns about unsaved changes. The saved exclusion removes every wait sample for that order (menu items, first serving, completion), without removing sales or item counts. It defaults to false for existing and new orders.

Manual closure is available in the order book to POS, kitchen, counter (WAITER), and admin staff. The redundant admin 注文の管理 card and its API have been removed. A confirmation is required in the UI and the dedicated staff endpoint requires confirm=true plus the displayed order version. Stale orders and unconfirmed/unpaid/failed/canceled/completed orders cannot be closed. The server preserves the current note and wait-statistics exclusion setting rather than accepting replacements from the browser.

The action serves outstanding items at the correction time under the acting staff account, preserves earlier serving timestamps, consumes available ready stock without going negative, clears the active call, and appends 手動完了 to the note. It does not change payments or invent cooking timestamps. The audit action is MANUAL_CLOSURE and records the staff actor ID/type, original item states, exact newly served item IDs, completion timestamp, and stock changes. The order version advances to block stale undo. Wait-statistics exclusion remains an independent saved setting in sales inspection.

**営業時間のみ表示** defaults on. Charts keep their existing 09:00–18:00 business-hours boundary, tightened around activity; switching it off displays the full JST calendar day, 00:00–24:00. This is a display setting and does not filter daily sales totals. Out-of-hours-only activity still produces a valid chart range. Long chart labels are spaced to remain readable.

The additive migration `20261017050000_order_wait_stats_exclusion` adds a default-false order field. Preview builds never apply migrations automatically. For this feature the single pending migration was explicitly applied before publishing the preview; existing order contents and payment states were preserved.

Checks: `scripts/order-corrections.test.ts` exercises authorization, stale writes, manual completion, stock limits, note editing, wait exclusion and sales preservation using mocked data. `scripts/order-corrections-browser-check.ts` checks staged saving, cancellation, default business-hours filtering, order-book closure for every staff role, canceled confirmations, completed-note editing, Japanese headings and phone layout without changing real orders.
