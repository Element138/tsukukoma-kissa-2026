# Order corrections and wait statistics

Notes may be edited after completion or failure by POS/admin users from the order book. Sales order inspection also lets POS/admin users stage a note and the order's wait-statistics exclusion together, then commit with **すべて保存**. Closing the panel or switching orders/dates warns about unsaved changes. The saved exclusion removes every wait sample for that order (menu items, first serving, completion), without removing sales or item counts. It defaults to false for existing and new orders.

The admin **注文の管理** card lists up to 100 open orders and can retrieve a past order by number. Its note, exclusion, and manual-completion drafts participate in the existing admin **すべて保存** action. Hidden drafts from earlier searches are included in that save. Discard/reload is explicit. The batch is transactional, and a stale order version blocks the entire batch rather than overwriting intervening work.

Manual closure exists only on the admin screen and admin API. It requires an explicit confirmation and a confirmed, paid/payment-skipped, nonterminal order without canceled items. It sets outstanding items served at the correction time by that administrator, preserves earlier serving timestamps, clears the active call, and appends `manual closure` to the note. Available ready stock is consumed up to the required quantity, never below zero; missing ready stock is permitted by this explicit correction. It creates no fictitious cooking timestamps or payment results. Audit entries and order events preserve the correction, and the order version advances to invalidate stale undo operations. Manual closure does not automatically exclude an order from wait statistics; the separate checkbox controls that choice.

**営業時間のみ表示** defaults on. Charts keep their existing 09:00–18:00 business-hours boundary, tightened around activity; switching it off displays the full JST calendar day, 00:00–24:00. This is a display setting and does not filter daily sales totals. Out-of-hours-only activity still produces a valid chart range. Long chart labels are spaced to remain readable.

The additive migration `20261017050000_order_wait_stats_exclusion` adds a default-false order field. Preview builds never apply migrations automatically. For this feature the single pending migration was explicitly applied before publishing the preview; existing order contents and payment states were preserved.

Checks: `scripts/order-corrections.test.ts` exercises authorization, stale writes, manual completion, stock limits, note editing, wait exclusion and sales preservation using mocked data. `scripts/order-corrections-browser-check.ts` checks staged saving, cancellation, default business-hours filtering, admin global save, completed-note editing, Japanese headings and phone layout without changing real orders.
